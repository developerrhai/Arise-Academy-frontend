# Push Notification API Technical Integration Guide

This technical document outlines the integration specifications, payload definitions, authentication requirements, and client-side setup details for the **Push Notification Module**. 

Frontend web developers (Next.js/React) and mobile app developers (iOS/Android/React Native/Flutter) should follow these guidelines to register device tokens and trigger or receive push notifications.

---

## 1. System Overview

The Notification Architecture relies on **Firebase Cloud Messaging (FCM)**.

```
+------------------------------------+        +-------------------------+        +--------------------------+
|  Mobile App / Web Client (FCM)     |        |   Arise Academy Backend    |        |   Firebase Cloud (FCM)   |
+------------------------------------+        +-------------------------+        +--------------------------+
                  |                                        |                                  |
   1. Request Permission & Get Token                       |                                  |
   ---------------------------------                       |                                  |
                  |                                        |                                  |
   2. Register Token                                       |                                  |
   ------------------------------------------------------->|                                  |
                  |  POST /api/notifications/register-token|                                  |
                  |  Headers: Bearer <JWT>                 |                                  |
                  |                                        |                                  |
                  |                                  3. Admin Triggers Push                   |
                  |                                  ----------------------                   |
                  |                                        | (Bulk/Single/Filtered)           |
                  |                                        |                                  |
                  |                                        | 4. Send Multicast Payload        |
                  |                                        |--------------------------------->|
                  |                                        |                                  |
                  |  5. Receive Push Message               |                                  |
                  |<--------------------------------------------------------------------------|
```

---

## 2. Authentication

All notification API endpoints require a **Bearer JWT Token** in the HTTP header:

```http
Authorization: Bearer <user_jwt_token>
Content-Type: application/json
```

The user's `id` and `role` (`STUDENT`, `TEACHER`, or `ADMIN`) are automatically extracted from the JWT token.

---

## 3. Base URLs

- **Development / Staging Base URL:** `http://localhost:5000/api/notifications` (or environment-specific server port)
- **Production Base URL:** `https://your-domain.com/api/notifications`

## 4. API Endpoints Specification

### 4.1 Register Device FCM Token

Clients **MUST** invoke this endpoint immediately after authentication, on application startup, or when FCM refreshes the token.

- **Endpoint:** `POST /api/notifications/register-token`
- **Auth Required:** Yes (`STUDENT`, `TEACHER`, or `ADMIN`)

#### Request Body
```json
{
  "token": "fcm_device_token_string_here",
  "deviceType": "web" // Options: "web", "android", "ios"
}
```

#### Field Description
| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `token` | String | Yes | FCM Registration Token generated by the client Firebase SDK. |
| `deviceType` | String | No | Target platform identifier: `"web"`, `"android"`, `"ios"`. Default is `"web"`. |

#### Response `200 OK`
```json
{
  "success": true,
  "message": "FCM Token registered successfully."
}
```

## 4.2 Send Push Notification to Single User (Admin Only)

- **Endpoint:** `POST /api/notifications/send-single`
- **Auth Required:** Yes (`ADMIN` role only)

#### Request Body
```json
{
  "userId": 101,
  "userRole": "STUDENT",
  "title": "Assignment Reminder",
  "body": "Your Mathematics homework is due tomorrow.",
  "data": {
    "screen": "homework_detail",
    "homeworkId": "45"
  }
}
```

#### Field Description
| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `userId` | Integer / String | Yes | Target user's database ID. |
| `userRole` | String | Yes | Role of target user (`STUDENT`, `TEACHER`, `ADMIN`). |
| `title` | String | Yes | Notification title visible in notification tray. |
| `body` | String | Yes | Notification body text. |
| `data` | Object | No | Key-value string dictionary for deep-linking / custom payload. |

#### Response `200 OK`
```json
{
  "success": true,
  "message": "Notification sent successfully.",
  "results": {
    "successCount": 1,
    "failureCount": 0
  }
}
```

---

## 4.3 Send Bulk Notification to Entire Role (Admin Only)

- **Endpoint:** `POST /api/notifications/send-bulk`
- **Auth Required:** Yes (`ADMIN` role only)

#### Request Body
```json
{
  "targetRole": "STUDENT",
  "title": "Holiday Announcement",
  "body": "The academy will remain closed this Friday.",
  "data": {
    "screen": "announcements"
  }
}
```

#### Field Description
| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `targetRole` | String | Yes | `"STUDENT"`, `"TEACHER"`, or `"ALL"`. |
| `title` | String | Yes | Notification title. |
| `body` | String | Yes | Notification content. |
| `data` | Object | No | Key-value pairs for app navigation. |

#### Response `200 OK`
```json
{
  "success": true,
  "message": "Bulk push notification completed.",
  "stats": {
    "totalTokens": 250,
    "successCount": 248,
    "failureCount": 2
  }
}
```

## 5. Client Integration Rules (App & Web)

### 5.1 Web Integration (Next.js / React)

1. **Service Worker Registration**: Place `firebase-messaging-sw.js` in the public root folder (`public/firebase-messaging-sw.js`).
2. **Notification Permission Request**:
   ```javascript
   const permission = await Notification.requestPermission();
   if (permission === 'granted') {
     const token = await getToken(messaging, { vapidKey: 'YOUR_VAPID_KEY' });
     if (token) {
       // Call POST /api/notifications/register-token
     }
   }
   ```
3. **Foreground Message Listener**: Handle messages received while app tab is actively focused using `onMessage(messaging, (payload) => { ... })`.

---

## 5.2 Mobile App Integration (React Native / Flutter / Android / iOS)

1. **Token Refresh Listener**: Listen to token lifecycle events (e.g. `messaging().onTokenRefresh(...)`) and post updated tokens to `/api/notifications/register-token`.
2. **Background / Terminated Push Handling**: Ensure your app handles the custom payload dictionary inside `data`:
   ```json
   {
     "screen": "homework_detail",
     "homeworkId": "45"
   }
   ```
3. **Deep Linking**: Route users to the corresponding screen based on `data.screen`.

## 6. Error Codes & Troubleshooting

| HTTP Status | Message / Reason | Solution |
| :--- | :--- | :--- |
| `401 Unauthorized` | Missing or invalid Bearer token. | Re-authenticate user and refresh JWT token. |
| `403 Forbidden` | Insufficient permissions (Non-admin invoking admin endpoints). | Endpoint requires `ADMIN` role. |
| `400 Bad Request` | Missing required parameters (`token`, `title`, `body`). | Check JSON request payload structure. |
| `500 Internal Error`| FCM Service configuration issue. | Verify backend Firebase Service Account configuration. |
